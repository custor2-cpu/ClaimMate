# 공정거래위원회 소비자 민원학습데이터 전처리 & 기술 스택

`data/raw/공정거래위원회_소비자 민원학습데이터 모범상담 사례_20211227.csv`가 실제 ML
파이프라인에 들어가기까지의 전체 흐름과 사용 기술 스택을 정리한다.

## 1. 원본 데이터의 문제와 1회성 빌드 스크립트 (`api/ml_engine/build_case_bank.py`)

원본 CSV는 `사건번호, 상담제목, 상담내용, 답변내용` 4개 컬럼만 있고 **카테고리 라벨도,
환급 성공/실패 라벨도 없다.** 그래서 매 요청마다 원본을 파싱하지 않고, 배포 전에 한 번만
실행해 정제된 `case_bank_data.json`(425건)을 만들어둔다.

- **로드**: `pandas.read_csv(..., encoding="utf-8-sig", engine="python", on_bad_lines="skip")`
  — 공공데이터 특유의 BOM과 줄바꿈 깨짐/불량 행을 건너뛰도록 처리
- **카테고리 부여(규칙 기반)**: 라벨이 없으므로 `제목+본문` 텍스트에서 14개 카테고리별
  키워드 리스트(예: 의료/병원 → "병원","진료","수술"...)와 매칭 점수를 계산해
  **가장 많이 매칭된 카테고리**를 배정한다. 매칭 점수가 0이면(어느 카테고리에도 안
  맞으면) 해당 레코드는 버린다.
- **성공확률 근사 라벨링**: 실측 라벨이 없어서, 답변(`답변내용`)의 어조에서
  "가능합니다/인정됩니다"류 긍정 신호와 "어렵습니다/거부할 수 있습니다"류 부정 신호
  단어 등장 횟수를 세어 `65 + (긍정-부정)×8`을 30~90 범위로 clip한
  `base_success_rate`를 근사치로 부여한다.
- **텍스트 길이 제한**: 상담내용 400자, 답변 160자, 제목(=dispute_type) 80자로 잘라
  저장 크기와 프롬프트 토큰 비용을 관리한다.
- **결과**: 425건. 카테고리 분포는 의료/병원 153건으로 최다, 체육시설/헬스장 4건·
  화장품/미용 6건 등 극소수 — 이 불균형 때문에 `predictor.py`에 `SYNTHETIC_CASES`
  (수작성 94건)를 추가로 합쳐 희소 카테고리를 보강한다.

## 2. 런타임 전처리 (`api/ml_engine/cleaner.py`)

사용자가 매 요청 때 입력하는 텍스트(그리고 케이스뱅크 텍스트도 동일 파이프라인)를 정제한다.

- **PII 마스킹**: 정규식으로 전화번호/주민등록번호/이메일/카드번호를 `[전화번호]` 등으로 치환
- **노이즈 제거**: 한글·영문·숫자·기본 문장부호(`.,!?%~()`) 외 특수문자를 공백으로
  치환 후 다중 공백 정규화
- **파생변수 생성(Pandas/NumPy)**: `text_length`, `word_count`, 15개 핵심 불만
  키워드(환불/위약금/하자/해지/청약철회 등)의 등장 여부를 `kw_*` 플래그 컬럼으로,
  그 합을 `keyword_score`로 생성
- **수치 피처 행렬화**: `text_length/200`, `word_count/40`(각각 0~3 clip)과
  `keyword_score` 비율, 15개 키워드 플래그를 `np.column_stack`으로 묶어 모델
  입력용 수치 피처 행렬을 생성

## 3. 분류/추론 엔진 (`api/ml_engine/predictor.py`)

- **벡터화**: `TfidfVectorizer(analyzer="char_wb", ngram_range=(2,4))` — 형태소
  분석기(KoNLPy 등)는 JVM 의존성 때문에 서버리스 환경에 부적합해서, 조사/어미
  변화에도 안정적인 **문자 단위 n-gram**을 채택
- **결합**: `scipy.sparse.hstack`으로 TF-IDF 희소행렬 + 수치 피처 행렬을 하나로 결합
- **분류**: `LogisticRegression`으로 대분류 카테고리 예측 (세부 dispute_type은
  표본이 적어 분류기 대신 유사사례 검색 Top-1에서 가져옴)
- **유사사례 검색**: 분류 신뢰도가 임계값(0.35) 이상이면 같은 카테고리 내에서,
  애매하면 `KMeans` 군집 전체로 후보를 넓혀 `cosine_similarity`로 최종 Top-3 매칭
- **성공확률 산출**: `0.55×분류신뢰도 + 0.45×유사사례 평균 base_success_rate`
- **캐싱**: subprocess로 매 요청마다 새 프로세스가 뜨는 구조라 매번 재학습하면
  ~7초가 걸리므로, 학습된 벡터라이저/분류기/K-Means를 `joblib`으로
  `_model_cache.joblib`에 캐시하고 케이스뱅크 mtime+건수를 캐시 키로 사용해
  데이터가 바뀔 때만 재학습

## 기술 스택 요약

| 역할 | 라이브러리 |
|---|---|
| CSV 로드/DataFrame 처리 | Pandas |
| 수치 피처 벡터 연산 | NumPy |
| TF-IDF, 분류, 군집화, 유사도 | Scikit-learn (`TfidfVectorizer`, `LogisticRegression`, `KMeans`, `cosine_similarity`) |
| 희소행렬 결합 | SciPy (`csr_matrix`, `hstack`) |
| 모델 캐싱 | joblib |
| PII 마스킹/노이즈 제거 | 표준 `re` 정규식 |
| 배포 실행 | Vercel Python Runtime(`api/ml_predict.py`) 또는 로컬 subprocess |

핵심 설계 포인트는 **"라벨 없는 원시 상담 데이터를 규칙 기반으로 1회 라벨링해두고,
무거운 형태소 분석 없이 char n-gram TF-IDF로 서버리스 환경에서도 가볍게 추론"**하는
구조다.
