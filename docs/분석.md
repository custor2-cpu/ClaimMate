# ClaimMate 분석 알고리즘

`api/ml_predict.py`는 진입점(HTTP 핸들러)이고, 실제 분석 알고리즘은
`api/ml_engine/predictor.py`에 있다. 4단계 알고리즘을 수식과 함께 정리한다.

## 1. 텍스트 벡터화 — Character n-gram TF-IDF

```python
TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 4), min_df=1)
```

- **단어 단위가 아니라 문자 단위(char_wb) n-gram**을 쓴다. 단어 경계(word boundary)
  안에서 2~4글자 연속 조합을 토큰으로 추출한다. 예: "위약금" → `위약`, `약금`,
  `위약금`, ` 위약`, `약금 ` 등
- **왜 문자 단위인가**: 한국어는 "위약금을/위약금이/위약금은"처럼 조사가 붙어
  단어 단위 토큰화 시 같은 의미가 다른 토큰으로 흩어진다. 형태소 분석기(KoNLPy)를
  쓰면 이 문제를 정확히 풀 수 있지만 JVM 의존성이 서버리스에 부적합해서, 조사
  변화에 어느 정도 강건한 char n-gram으로 대체한 것이다.
- **TF-IDF 가중치**: 각 n-gram의 `TF(문서 내 등장빈도) × IDF(log(전체 문서수/해당
  n-gram이 등장한 문서수))`로 가중치를 매겨, 흔한 조합(예: 조사 관련)보다 특이한
  조합에 더 큰 가중치를 부여한다.

## 2. 피처 결합

```python
x = hstack([tfidf_matrix, csr_matrix(numeric_features)])
```
TF-IDF 희소벡터(수천 차원) 뒤에 `cleaner.py`가 만든 수치 피처(길이·단어수·15개
키워드 플래그, 총 18차원)를 수평으로 이어 붙여 하나의 입력 벡터로 만든다. 텍스트의
통계적 패턴만이 아니라 "환불/위약금 키워드가 실제로 있는가" 같은 명시적 신호도
분류기가 직접 보게 하려는 설계다.

## 3. 분류 — Logistic Regression (다중 클래스)

```python
LogisticRegression(max_iter=3000).fit(x_train, categories)
```
- 14개 카테고리에 대한 **다중 클래스 로지스틱 회귀**(scikit-learn 기본: multinomial
  softmax, lbfgs solver)로, 각 카테고리에 속할 확률 `P(category|x)`를 출력한다.
- `predict_proba()`의 최댓값 인덱스를 카테고리로, 그 확률값을 `confidence`로 사용한다.
- 세부 `dispute_type`(예: "중도 해지 위약금 과다 청구")은 라벨 종류가 너무 많고
  카테고리당 표본도 적어 분류기로 학습하지 않고, 뒤 단계의 유사사례 검색 1위
  결과에서 그대로 가져온다.

## 4. 유사 사례 검색 — 신뢰도 기반 후보군 전환 + Cosine Similarity

```python
if confidence >= 0.35:
    candidates = 같은 카테고리 전체
else:
    candidates = KMeans 예측 군집 전체
similarity = cosine_similarity(입력벡터, 후보 TF-IDF 행렬)
top3 = 유사도 상위 3건
```
- **분류 신뢰도(confidence) ≥ 35%**: 분류기를 신뢰하고 같은 카테고리 내부에서만
  코사인 유사도로 검색한다 (정밀도 우선).
- **confidence < 35%**(애매한 입력): 분류기를 믿지 않고, 대신
  `KMeans(n_clusters=카테고리수, n_init=10, random_state=42)`로 미리 군집화해둔
  **군집 전체**를 후보로 넓혀 검색한다 (재현율 우선 — 오분류 시에도 비슷한 사례를
  놓치지 않도록).
- 이때 KMeans는 카테고리 예측이 아니라 "텍스트 유사도 기반 군집 구조"만
  만들어두는 **보조 안전망** 역할이다.
- 코사인 유사도: `cos(θ) = (A·B)/(|A||B|)` — TF-IDF 벡터 간 방향 유사도로, 텍스트
  길이에 영향받지 않고 "어떤 단어(n-gram) 조합이 겹치는가"만 본다.

## 5. 구제 성공확률 산출 — 가중 블렌딩

```python
success_rate = 0.55 × confidence×100 + 0.45 × (Top-3 유사사례 base_success_rate 평균)
```
- 분류기의 **확신도(confidence)** 와 실제 과거 사례의 **처리결과 근사치
  (base_success_rate, build_case_bank.py가 답변 어조에서 추정)** 를 55:45로
  블렌딩한다.
- 순수 분류 확률만 쓰면 "분류는 확신하지만 실제 처리결과는 나쁜 유형"을 반영 못
  하고, 유사사례 평균만 쓰면 분류가 틀렸을 때 엉뚱한 사례 기준이 섞이므로, 두
  신호를 함께 쓴다.
- `np.clip(raw_score, 5.0, 97.0)`으로 극단값(0%/100%)은 피한다.

## 정리

이 알고리즘은 통계적 지도학습(로지스틱 회귀)과 비지도학습(K-Means)을 신뢰도
임계값으로 스위칭하며 결합하고, 최종 점수는 "분류기 확신도"와 "과거 사례 실측
근사치"의 가중평균이라는 게 핵심 구조다.

## 참고: 사용자가 고른 카테고리는 분류에 반영되지 않음

`predictor.predict(text, amount)`는 텍스트만 보고 카테고리를 자체 예측하며,
`DisputeForm`에서 사용자가 직접 고른 카테고리는 결과 JSON의
`input.category_hint`에 참고용으로만 저장될 뿐 실제 분류/유사사례 검색 로직에는
입력되지 않는다.
